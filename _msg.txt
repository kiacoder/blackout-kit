fix: 5 critical and 30 high findings from the CLI audit

Critical:
- BK-001 save_configs() refused to overwrite a library that failed to LOAD.
  A caller that loaded (got an error), mutated the empty list and saved would
  otherwise replace the user's whole library with nothing. force=True exists
  for an explicit reset.
- BK-002 the QoS shaper opened a WinDivert handle for ALL packets and never
  re-injected them - wiring it up would have blackholed the machine. It now
  refuses to open until a re-inject loop exists.
- BK-003 IKEv2 dialled with Connect-VpnConnection, a cmdlet that does not
  exist (Windows ships Add/Get/Set/Remove-VpnConnection but nothing that
  dials). rasdial is the documented path; the engine was dead on every host.
- BK-004 POSIX arrow keys never worked: sys.stdin.read(1) pulled the whole
  ESC[A into Python's buffer, so select() on the fd saw nothing pending and
  every arrow arrived as a bare Escape. The reader uses os.read on the fd.
- BK-005 setup export stripped credentials that import required, so a backup
  could never be restored. It exports the full document now and says so.
- BK-073 torrents bypassed the tunnel entirely: the libtorrent session had no
  proxy, and libtorrent ignores http_proxy and the WinINET registry setting,
  so every announce and peer connection leaked the real IP. The session now
  forces SOCKS and refuses to start when nothing is listening on it.

High:
- BK-006/007/008/009 the dashboard was unreachable, crashed on launch (Live()
  was handed a generator), read state keys the daemon never writes and
  reported uptime/memory as 0. It is a real command now, renders in a loop,
  derives connected/throughput from the keys that exist, and the daemon
  writes started_ts and real RSS.
- BK-010/075 Request was imported inside create_app() while the module uses
  postponed annotations, so FastAPI treated it as a query parameter: every
  webhook POST/DELETE returned 422 and /openapi.json returned 500.
- BK-011 the command browser returned item.key from a str, crashing on every
  successful selection.
- BK-012/013 the web dashboard loaded Chart.js from a CDN (blank on exactly
  the networks this tool is for) and the SSE stream ended after 5 events. The
  chart is drawn on a canvas with no external script, and the stream stays
  open.
- BK-014/015/016 ScanIPsC returns C heap memory that Python could not free;
  FreeCString is exported and called. The scanner also returned [] on every
  non-Windows platform and blocked the event loop. It falls back to the
  asyncio implementation already in the module and runs in a worker thread.
- BK-017 FAKE_SNI was parsed and never used - the native engine's headline
  feature did not exist. engine/sni_rewrite.go rewrites the server_name and
  recomputes every enclosing length; the relay injects it before fragmenting.
- BK-018 TUN mode emitted inet4_address and inbound sniff, removed in sing-box
  1.12/1.13, so the managed binary rejected the config. Migrated to address[]
  and the route-action form, with the typed DNS schema.
- BK-019 WireGuard leaked the device on every failed start and then refused
  all restarts; MTU was ignored and sections were not parsed. Rollback on
  failure, section-aware parsing, MTU honoured.
- BK-020 the WARP/Psiphon DLL had no start guard and no panic recovery, so a
  panic in warp-plus killed the Python host. Both are guarded now, and the
  phantom Psiphon HTTP port is no longer advertised.
- BK-021 Linux "system proxy" set env vars inside our own process and returned
  True. It now uses gsettings/kwriteconfig and reports honestly when there is
  no desktop backend.
- BK-022/023 the daemon's ENGINE_MAP was missing six registered engines and
  the settings validators rejected the newest ones. Both derive from
  ENGINE_REGISTRY now, so the registry docstring is true again.
- BK-024 query parameters were percent-decoded twice.
- BK-025 subscription import and setup export crashed the TUI on a network or
  filesystem error.
- BK-026 probes released a module-global semaphore they may not have acquired.
- BK-055 a verified download never re-pinned, so the next launch of an updated
  binary was refused with "hash mismatch".
- BK-056 the manifest lived inside bins/, the directory it protects, and the
  in-process DLLs were never verified. It moved to app-data and both DLLs are
  checked before CDLL.
- BK-057 the release shipped no blackout_core.dll or blackout_warp.dll even
  though BIN_REGISTRY requires one. CI builds and publishes both.
- BK-058 a catalog entry name became a filename with no validation.
- BK-059 a download's filename came raw from the URL, backslashes included.
- BK-074 the torrent session called libtorrent 1.x API removed in the pinned
  2.0.11, and only caught ImportError.
- BK-076 RBAC was decorative: nothing outside rbac.py called require(). The
  CLI now checks the policy for every subcommand, and exits 3 when denied.
- BK-077 the ad blocker only understood hosts format, so the two blocklists it
  recommends imported zero rules and reported success.

Also: a test that patched os.name broke pathlib on Windows (Path consults
os.name), so the spawn check uses sys.platform instead.

1538 tests pass.
